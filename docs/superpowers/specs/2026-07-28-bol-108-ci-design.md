# BOL-108: CI no GitHub Actions (lint, typecheck, test, build)

**Issue:** [BOL-108](https://rafaelhjahn.youtrack.cloud/issue/BOL-108)  
**Épico:** [BOL-10](https://rafaelhjahn.youtrack.cloud/issue/BOL-10) — Frontend (betting-pool-app)  
**Depende de:** [BOL-105](https://rafaelhjahn.youtrack.cloud/issue/BOL-105) — ESLint + Prettier + lefthook + commitlint, [BOL-106](https://rafaelhjahn.youtrack.cloud/issue/BOL-106) — Vitest + Testing Library, [BOL-107](https://rafaelhjahn.youtrack.cloud/issue/BOL-107) — Playwright  
**Data:** 2026-07-28

## Objetivo

Pipeline de CI no GitHub Actions validando format, lint, typecheck, testes unitários (Vitest), testes E2E (Playwright) e build a cada push/PR nas branches `development` e `main`.

## Decisões de design

| Decisão      | Escolha                                                            |
| ------------ | ------------------------------------------------------------------ |
| Workflow     | `.github/workflows/ci.yml`, nome `Verify`                          |
| Trigger      | `push` + `pull_request` em `development` e `main`                  |
| Estrutura    | 1 job (`verify`), steps sequenciais                                |
| Steps        | format → lint → typecheck → test → playwright install → e2e        |
| Build        | Validado implicitamente pelo E2E (`webServer` já faz `pnpm build`) |
| Format no CI | Sim (`pnpm format`) — espelha o backend                            |
| E2E no CI    | Sim (`pnpm test:e2e`) — Vitest + Playwright smoke test             |
| Node/pnpm    | `.nvmrc` (`26.4.0`) + `pnpm/action-setup@v6` com cache             |
| Browsers     | `playwright install chromium --with-deps` (só no CI)               |
| Referência   | `betting-pool/.github/workflows/ci.yml` (adaptado para frontend)   |

## Abordagens consideradas

### A) Job único com build explícito — descartada

`format → lint → typecheck → test → build → e2e`

Build roda 2× (step separado + `webServer` do Playwright). Erro de build isolado, mas pipeline mais lenta.

### B) Dois jobs paralelos — descartada

`verify` (format…build) ∥ `e2e` (browsers + test:e2e)

Feedback mais rápido, mas 2× `pnpm install` e complexidade desnecessária para 1 smoke test.

### C) Job único sem build separado — escolhida

`format → lint → typecheck → test → install browsers → e2e`

Sem build duplicado. Falha de build aparece no step E2E (via `webServer`). Simples e alinhada ao estágio atual do projeto.

| Arquivo                    | Ação      | Responsabilidade                           |
| -------------------------- | --------- | ------------------------------------------ |
| `.github/workflows/ci.yml` | Criar     | Workflow de CI completo                    |

## `.github/workflows/ci.yml`

```yaml
name: Verify

on:
  push:
    branches: [development, main]
    paths-ignore: &paths_ignore
      - ".vscode/**"
      - ".nvmrc"
      - "commitlint.config.js"
      - "lefthook.yml"
      - "README.md"
      - "docs/**"
  pull_request:
    branches: [development, main]
    paths-ignore: *paths_ignore

jobs:
  verify:
    name: Verify
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v6

      - name: Setup pnpm
        uses: pnpm/action-setup@v6
        with:
          cache: true

      - name: Setup Node.js
        uses: actions/setup-node@v6
        with:
          node-version-file: .nvmrc

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Format
        run: pnpm format

      - name: Lint
        run: pnpm lint

      - name: Typecheck
        run: pnpm typecheck

      - name: Test
        run: pnpm test

      - name: Install Playwright browsers
        run: pnpm exec playwright install chromium --with-deps

      - name: E2E
        run: pnpm test:e2e
```

### Notas do workflow

- `actions/checkout@v6`, `pnpm/action-setup@v6`, `actions/setup-node@v6` — mesmas versões do repo `betting-pool`
- `CI=true` é setado automaticamente pelo GitHub Actions
- `--with-deps` instala dependências de sistema do Chromium no Ubuntu runner
- Sem step `build` separado — o `webServer` do Playwright (`pnpm build && serve out`) valida o build estático

### `paths-ignore`

Adaptado do backend, removendo itens específicos de infra backend (`devbox`, `ministack`, `process-compose`, `.env.example`). Mudanças em `docs/` não disparam CI.

## Script `typecheck` (`package.json`)

```json
"typecheck": "tsc --noEmit"
```

TypeScript já é devDependency. `tsconfig.json` existente (`strict: true`, `noEmit: true`) é suficiente.

## Fluxo de execução no CI

```
push/PR → development | main
  └─ Job: verify (ubuntu-latest)
       ├─ checkout + setup pnpm/node + install
       ├─ pnpm format        → Prettier check
       ├─ pnpm lint          → ESLint
       ├─ pnpm typecheck     → tsc --noEmit
       ├─ pnpm test          → Vitest
       ├─ playwright install chromium --with-deps
       └─ pnpm test:e2e
            └─ webServer: pnpm build → serve out → smoke test
```

## Error handling

Falhas que quebram o CI:

| Step      | Comando          | O que falha                                      |
| --------- | ---------------- | ------------------------------------------------ |
| Format    | `pnpm format`    | Código mal formatado                             |
| Lint      | `pnpm lint`      | Violações ESLint                                 |
| Typecheck | `pnpm typecheck` | Erros TypeScript                                 |
| Test      | `pnpm test`      | Testes Vitest falhando                           |
| E2E       | `pnpm test:e2e`  | Smoke test falhando **ou** `next build` falhando |

Qualquer step com exit code ≠ 0 falha o job e bloqueia merge (se branch protection estiver configurada).

## README

Adicionar `pnpm typecheck` na seção Scripts e nota breve sobre CI:

```bash
pnpm typecheck  # TypeScript (tsc --noEmit)
```

Menção de que o workflow `Verify` roda automaticamente em PRs para `development` e `main`.

## Fora do escopo

- Upload de artefatos Playwright (`playwright-report/`, `test-results/`)
- Coverage no CI
- Branch protection rules no GitHub (config manual no repo)
- Matrix de browsers (só Chromium)
- Job `build` separado (build validado via E2E)
- Deploy / preview environments

## Critérios de aceite

1. Workflow `Verify` passa em uma PR de teste
2. Falha de format, lint, typecheck, test ou E2E quebra o CI
3. `pnpm typecheck` funciona localmente
